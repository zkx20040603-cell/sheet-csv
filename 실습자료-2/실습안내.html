0. 2부 흐름

시간 할 일 이 문서
55–100분 함께 만들어 보기: 시트 → 웹에 게시 → 로컬 실행 → 저장소 → 실행 1–6
100–145분 팀별로 해 보기 (진행은 수업에서 안내) 7
145–150분 기록과 6주차 준비 8

준비물 구글 계정, GitHub 계정, 실습자료의 sheet-content-project 폴더, Python 3(4주차와 같음). 웹에 게시 메뉴는 개인 구글 계정에서 바로 쓸 수 있습니다.

단계마다 확인 줄까지 마치고 다음 단계로 넘어갑니다.

1. 시트 만들기 · 5분

  1. 구글 시트에서 새 스프레드시트를 만들고 제목을 시트 목록 연습으로 적습니다.
  2. 파일 → 가져오기 → 업로드에서 sheet-content-project/sample.csv를 고르고, 가져오기 위치를 현재 시트 바꾸기로 정합니다.
  3. 맨 아래에 내 행을 두 개 더 적습니다. 하나는 공개 Y, 하나는 공개 N으로 둡니다. 적을 내용은 강의 핵심정리의 예시 데이터에서 골라도 됩니다.

확인 1행이 제목, 내용, 분류, 링크, 공개이고, 공개 열에는 Y와 N만 있습니다.

2. 웹에 게시하기 · 5분

  1. 파일 → 공유 → 웹에 게시를 누릅니다.
  2. 링크 탭에서 게시할 시트(시트1)와 형식 쉼표로 구분된 값(.csv)을 고르고 게시 → 확인을 누릅니다.
  3. 나온 주소를 복사해 새 브라우저 탭에 붙여 넣습니다.

확인 브라우저에 쉼표로 구분된 글자가 보이고, 주소가 output=csv로 끝납니다.

3. 내 컴퓨터에서 먼저 실행 · 10분

터미널에서 예제 폴더로 이동해 게시 주소를 넣어 실행합니다. 주소는 큰따옴표로 감쌉니다.

cd sheet-content-project
python3 main.py --csv "복사한_게시_주소" --output _site/index.html

Windows에서는 python3 대신 python을 씁니다. 터미널에 아래처럼 나오면 성공입니다. 숫자는 시트의 행 수에 따라 달라집니다.

데이터: 구글 시트(웹에 게시한 CSV)
공개 11개 · 비공개 2개 · 오늘의 추천 날짜 2026-09-30
HTML 생성 완료: _site/index.html

_site/index.html을 브라우저로 엽니다.

확인 내가 적은 Y 행이 카드로 보이고 N 행은 없습니다. 검색창과 분류 필터가 동작합니다.

4. 저장소 만들고 파일 올리기 · 10분

4주차와 같은 방법으로 브라우저에서 올립니다.

  1. GitHub에서 New repository → 이름 sheet-list → Public → Create repository.
  2. Add file → Upload files로 main.py, site.json, sample.csv, README.md를 올리고 Commit changes를 누릅니다.
  3. Add file → Create new file의 파일 이름 칸에 .github/workflows/sheet_site.yml을 그대로 입력합니다. 예제의 같은 파일을 텍스트 편집기로 열어 내용 전체를 붙여 넣고 Commit changes를 누릅니다.
  4. Settings → Pages → Source를 GitHub Actions로 정합니다.

확인 저장소 첫 화면에 .github 폴더와 main.py가 보이고, 워크플로 파일 위쪽 경로가 sheet-list / .github / workflows / sheet_site.yml입니다.

5. 게시 주소를 저장소 변수로 · 5분

  1. Settings → Secrets and variables → Actions를 엽니다.
  2. Variables 탭 → New repository variable을 누릅니다.
  3. Name에 SHEET_CSV_URL, Value에 게시 주소를 넣고 Add variable을 누릅니다.

확인 Variables 탭 목록에 SHEET_CSV_URL이 보입니다. 게시 주소는 공개돼도 되는 값이라 Variables에 둡니다. 6주차의 인증키는 Secrets에 둡니다.

6. 실행하고 시트 고쳐 보기 · 10분

  1. Actions → Sheet Content Site → Run workflow를 누릅니다.
  2. build의 Build page from Google Sheet 단계에서 데이터 출처와 공개·비공개 개수를 읽습니다.
  3. deploy가 끝나면 실행 화면의 주소(또는 Settings → Pages의 주소)를 엽니다.
  4. 시트에 행을 하나 더 적고 다시 Run workflow를 누릅니다. 새 카드가 보이면 연결이 끝난 것입니다.
확인할 것 해 보는 방법 기대 결과
시트 수정 반영 행 추가 → 다시 실행 새 카드가 보임
비공개 행 한 행의 공개를 N으로 → 다시 실행 카드가 사라지고 ‘비공개 n개 제외’
검색 결과 없음 없는 단어로 검색 결과 없음 안내
잘못된 데이터 시트를 CSV로 내려받아 1행 열 이름 하나를 바꾸고 로컬 실행 실행이 멈추고 이유와 현재 열 출력
휴대전화 폭 휴대전화로 공개 주소 열기 가로 넘침 없음

잘못된 데이터는 원본 시트 대신 내려받은 CSV(파일 → 다운로드 → 쉼표로 구분된 값)로 실험합니다.

python3 main.py --csv 내려받은파일.csv --output _site/index.html

게시한 시트의 수정이 CSV 주소에 반영되기까지 몇 분 걸릴 수 있습니다. 새 내용이 보이지 않으면 잠시 뒤 다시 실행합니다.

여기까지 되면 내 공개 주소의 바닥글에 ‘데이터: 구글 시트(웹에 게시한 CSV)’와 생성 시각이 보입니다. 이 주소를 활동기록에 적습니다.

7. 팀별로 해 보기

진행 방법은 수업에서 교수자가 안내합니다. 적용할 때 아래 내용을 참고합니다.

  • 목표 오늘 만든 흐름(시트 → CSV → Actions → Pages)을 팀 서비스의 데이터에 적용합니다.
  • 데이터 고르기 사람이 직접 적고 자주 고치는 목록이 시트에 잘 맞습니다. 강의 핵심정리의 예시 데이터를 참고합니다.
  • 적용 방법 예제 파일로 바꾸면 빠르게 연결됩니다. 이미 만든 화면을 살리려면 AI에게 연결을 요청합니다.
  • 확인 6절 표의 다섯 가지를 팀 서비스에서 다시 확인합니다.

이미 만든 코드에 연결할 때 쓰는 요청문입니다. sheet-content-project 폴더를 참고 자료로 함께 둡니다.

이 저장소의 main.py는 quotes.json을 읽어 웹페이지를 만든다.
이것을 환경 변수 SHEET_CSV_URL의 CSV(구글 시트 웹 게시 주소)를 읽도록 바꿔줘.
- 열 약속: 제목, 내용, 분류, 링크, 공개. 공개가 Y인 행만 쓴다.
- 열이 빠졌거나 공개 행이 없거나 링크가 http(s)로 시작하지 않으면 HTML을 만들지 말고 이유와 행 번호를 출력하고 멈춰줘.
- 지금 화면 디자인은 유지하고, 목록에 검색창과 분류 필터, 결과 없음 안내를 더해줘.
- 워크플로에서 ${{ vars.SHEET_CSV_URL }}을 main.py에 전달해줘.
- 참고 구현: sheet-content-project/main.py
먼저 바꿀 파일과 계획을 보여 주고, 내가 확인하면 진행해줘.

기존 저장소에 예제 파일을 넣을 때는 Pages에 배포하는 워크플로를 하나만 남깁니다(예: 4주차 daily_quote.yml 삭제). AI가 바꾼 내용은 git diff로 읽고 6절 표로 확인합니다.

8. 기록과 6주차 준비

  • 개인 활동기록을 TXT 또는 JSON으로 저장합니다.
  • 6주차 수업 전까지 공공데이터포털 준비를 보고 한국천문연구원_특일 정보 활용신청을 마칩니다. 관심 있는 API가 있으면 하나 더 신청합니다.
  • 개인 프로젝트 후보 두 개를 활동기록에 적어 옵니다. 6주차에 하나를 골라 범위를 정합니다.
