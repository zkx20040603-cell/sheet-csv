# 5주차 강의 핵심정리 · 구글 시트로 콘텐츠 관리

1부 강의를 한 장에 정리했습니다. 2부 실습 중에 옆에 열어 두고 봅니다.

## 1. 왜 구글 시트인가

4주차에는 문구를 바꾸려면 `quotes.json`을 고쳐 커밋했습니다. 콘텐츠를 구글 시트로 옮기면 편집 권한이 있는 사람 누구나 표에서 내용을 고치고, 코드는 그대로 둡니다.

| 역할 | 맡는 것 |
|---|---|
| 구글 시트 | 콘텐츠를 적고 고치는 화면 |
| 웹에 게시한 CSV 주소 | 프로그램이 콘텐츠를 읽는 입구 |
| GitHub Actions | 시트를 읽어 HTML을 만드는 실행 |
| GitHub Pages | 완성된 웹페이지 공개 |

## 2. 웹에 게시와 CSV

파일 → 공유 → **웹에 게시** → 시트(탭) 하나 선택 → 형식 **쉼표로 구분된 값(.csv)** → 게시. 이때 나오는 주소가 CSV 주소입니다.

CSV는 표를 쉼표로 구분한 글자로 적은 파일입니다. 칸 안에 쉼표나 따옴표가 있으면 칸 전체를 큰따옴표로 감쌉니다. 이 처리는 프로그램이 알아서 합니다.

```text
제목,내용,분류,링크,공개
커밋 전에 바뀐 줄 읽기,git diff로 바뀐 줄을 먼저 확인합니다.,Git,https://git-scm.com/docs/git-diff,Y
시트의 1행은 열 이름,"제목, 내용, 분류, 링크, 공개 열 이름을 지킵니다.",데이터,,Y
```

## 3. 두 가지 읽기 방법

| 구분 | 빌드 때 읽기 (오늘 실습) | 볼 때 읽기 (선택) |
|---|---|---|
| 읽는 주체 | GitHub Actions | 방문자의 브라우저 |
| 반영 시점 | 워크플로를 실행할 때 | 페이지를 새로고침할 때 |
| 좋은 점 | 화면이 바로 뜨고, 잘못된 데이터를 배포 전에 막음 | 시트 수정이 바로 보임 |
| 챙길 점 | 시트를 고친 뒤 다시 실행하거나 예약 실행 | 읽는 동안 빈 화면, 오류가 방문자 화면에 보임 |

## 4. 열 약속

시트의 1행은 프로그램과의 약속입니다. 이름이 바뀌면 프로그램이 이유를 알리고 멈춥니다.

| 열 | 필수 | 내용 |
|---|---|---|
| 제목 | 필수 | 카드 제목 |
| 내용 | 필수 | 한두 문장 설명 |
| 분류 | 선택 | 필터에 쓰는 분류 |
| 링크 | 선택 | `http://` 또는 `https://`로 시작하는 주소 |
| 공개 | 필수 | `Y`인 행만 웹에 표시 |

## 5. 저장소 변수와 비밀

| 구분 | 넣는 값 | 예 |
|---|---|---|
| Variables | 공개돼도 괜찮은 설정 | `SHEET_CSV_URL` (오늘) |
| Secrets | 비밀번호·인증키 | 공공데이터 인증키 (6주차) |

위치: 저장소 Settings → Secrets and variables → Actions. 워크플로에서는 `${{ vars.SHEET_CSV_URL }}`로 읽습니다.

## 6. main.py가 하는 일

```text
CSV 읽기 → 1행의 열 이름 확인 → 공개=Y 행 고르기 → 행마다 제목·내용·링크 확인
  → 오늘의 추천 + 검색·필터 목록 HTML 생성 → Pages 배포
```

## 7. 잘못된 데이터는 배포하지 않습니다

| 상황 | Actions 로그 |
|---|---|
| 웹에 게시하지 않은 주소 | CSV 대신 웹페이지가 왔습니다 |
| 열 이름이 다름 | 필수 열이 없습니다: 내용 / 현재 열: … |
| 공개=Y 행이 없음 | 공개 열이 Y인 행이 없습니다 |
| 링크가 `https://`로 시작하지 않음 | n행의 링크는 http:// 또는 https://로 시작해야 합니다 |
| 제목·내용이 빈 행 | n행의 제목이(가) 비어 있습니다 |

build가 멈추면 이전에 배포한 웹페이지가 그대로 유지됩니다. 로그의 행 번호를 보고 시트를 고친 뒤 다시 실행합니다.

## 8. 공개 범위

웹에 게시한 CSV는 주소를 아는 누구나 읽을 수 있습니다. 시트에는 웹에 보여도 되는 내용만 적습니다. 편집 권한은 함께 관리하는 사람에게만 주고, README에는 CSV 주소만 적습니다.

## 9. 시트로 관리하기 좋은 데이터 예시

사람이 직접 적고 자주 고치는 목록이 시트에 잘 맞습니다. 웹에 보여도 되는 정보만 적습니다.

| 예시 | 열 구성 예 | 화면에서 쓰기 |
|---|---|---|
| 학과·동아리 행사 일정 | 제목, 날짜, 장소, 분류, 링크, 공개 | 다가오는 행사 목록, 분류 필터 |
| 캠퍼스 주변 식당·카페 | 이름, 대표 메뉴, 가격대, 분류, 지도 링크, 공개 | 가격대·분류로 거르기 |
| 스터디 자료 링크 모음 | 제목, 설명, 과목, 링크, 공개 | 과목 필터와 검색 |
| 추천 도서·영상 | 제목, 한 줄 소개, 분류, 링크, 공개 | 오늘의 추천 한 항목 |
| 자주 묻는 질문(FAQ) | 질문, 답변, 분류, 공개 | 질문 검색 |
| 공모전·대외활동 모음 | 이름, 마감일, 주최, 링크, 공개 | 마감일 순 목록 |

예제 `main.py`는 제목·내용·분류·링크·공개 다섯 열을 씁니다. 날짜나 가격대처럼 다른 열을 화면에 쓰려면 `main.py`도 함께 고칩니다(AI에게 요청할 수 있습니다).

## 10. 오늘의 기준

- 시트를 고치고 다시 실행하면 공개 웹에 반영된다.
- 공개=N 행은 보이지 않고, 검색 결과가 없으면 안내가 나온다.
- 잘못된 데이터로 실행하면 build가 멈추고 로그에서 이유를 찾을 수 있다.
- 휴대전화 폭에서 가로 넘침이 없다.
